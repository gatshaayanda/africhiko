# Africhiko — Agent Operating Contract

## Product
Africhiko Proprietary Limited is a Botswana welding and steel fabrication business. The customer experience is the priority; administration follows once the customer enquiry flow works.

## Source foundation and workflow
Every new Admin Hub app must be cloned from `gatshaayanda/the-plug`. The source's `CLONING.md`, `AGENTS.md`, `AGENTS_REPO_LABELED.md`, `docs/ADMIN-HUB-APP-FACTORY-SOP.md` and `docs/CLONE-RESET-CHECKLIST.md` are mandatory. Read the actual applicable branch/version and follow its ordered gates. Reuse proven mechanisms only after tracing their dependencies; do not reuse source branding, business logic, credentials, production data or infrastructure.

Workflow: UNDERSTAND BRIEF → INSPECT THE PLUG → READ SOP → CLONE → RESET IDENTITY/INFRASTRUCTURE → VERIFY FOUNDATION → BUILD → VERIFY → CHECKPOINT.

Unexpected result: STOP → INSPECT REALITY → IDENTIFY FIRST FAILURE → FIX → VERIFY.

## Customer experience
Build a responsive, accessible storefront for gates/security, trailers, carports/sheds, beds/bunks, laser cutting and custom fabrication. Customers should be able to discover services, describe project dimensions/use/quantity/material preferences/location, optionally provide reference images/drawings, review and edit their enquiry, submit it, receive truthful acknowledgement and follow up. No registration requirement before an initial enquiry. Distinguish enquiries, quotations, accepted quotations, payments and confirmed work. Do not invent prices, stock, clients, certifications or delivery promises.

## Brand
Retain the welder-and-sparks concept. Use purple/violet, cyan/light blue, white and dark steel/black, with strong contrast and responsive typography.

## Security and infrastructure
Use dedicated Africhiko infrastructure. Never reuse The Plug's production credentials, customer records, database or hosting configuration. Enforce server-side authorization and default-deny data/storage rules. Protect secrets. Do not deploy, mutate production data or deploy rules without explicit authorization.

## PWA

**Mandatory install lock:** read [docs/PWA-INSTALLATION-LOCK.md](./docs/PWA-INSTALLATION-LOCK.md) before any install-related change. Keep the automated regression checks in `scripts/verify-identity.mjs`; do not weaken or remove them to pass a build. Installation is frozen during routine branding and feature work.
The website must work without installation. Capture Chromium's `beforeinstallprompt` early and call the native prompt directly from the explicit Install click when available; only show the install CTA after the browser offers that native prompt. Do not replace a missing native prompt with a misleading fake install/download dialog. iOS has no equivalent web API; give clear Add to Home Screen guidance. Embedded-browser handoff must preserve the requested URL and not force installation.

The 180×180 Apple icon and 192×192 / 512×512 PNG install icons are generated by `scripts/generate-pwa-icons.mjs` through npm's `prebuild` lifecycle. Keep this hook in `package.json`, declare the raster icons in both manifests, and verify PNG signatures/dimensions with `npm run verify:identity`. When changing PWA shell assets, increment the Africhiko-specific service-worker cache version. Verify manifest/icon validity, unique cache namespace, offline behavior, and Android/iOS installation separately.

## Engineering
Inspect source, branches, Git state, rules, schemas, environment variable names, workflows and deployment before edits. Make the smallest controlled changes, preserve working behavior, inspect diffs, and run the actual available checks: `npm ci`, `npm run verify:identity`, `npm run verify:clone-readiness` if present, `npx tsc --noEmit`, `npm run lint`, `npm run build`, and `git diff --check`. Report PASS / FAIL / NOT RUN / BLOCKED honestly. A build does not prove live integrations or device behavior.

## Checkpoint
Report repository, branch, commit, working-tree state, changed files, real verification results, push status, deployment status and next action. The owner handles Vercel deployment by default.
